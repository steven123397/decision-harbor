# 07 — 租约、心跳、全局容量与所有权接管

**What to build:** 多个 Worker 副本共享一个由数据库协调的全局并发上限，横向扩展不会突破 analytics 数据库容量。每个 Worker 通过租约和心跳维持执行所有权，租约过期后其他副本可以接管，接管期间查询运行保持 `running` 而不回退到排队；旧执行尝试永远不能发布状态或结果，迟到的 Worker 不能覆盖接管后的终态。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 全局并发上限由数据库协调，默认值为 4，不能只由单进程内计数控制
- [ ] 上限统计当前 generation 且租约未过期的有效执行所有权
- [ ] 上限不把已经失租但尚未物理停止的旧数据库活动计为有效所有权
- [ ] 2 个 Worker 副本同时运行时，数据库中未过期的有效执行所有权从不超过上限
- [ ] 任一查询运行在同一时刻从不存在两个可发布所有者
- [ ] Worker 定期续租；租约过期后其他副本可以接管
- [ ] 每次领取产生包含 Worker 标识和递增 generation 的执行尝试
- [ ] 接管期间查询运行保持 `running`，不回退到 `queued`
- [ ] 任何状态或结果发布都核对当前运行状态、执行尝试和 generation，旧 generation 的写入不产生效果
- [ ] 默认配置为并发 4、租约 15000ms、心跳 3000ms、轮询 250ms，且心跳严格小于租约
