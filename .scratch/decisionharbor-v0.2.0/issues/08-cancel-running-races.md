# 08 — 取消运行中的查询并裁决终态竞态

**What to build:** 让分析用户取消正在执行的查询，并由持久取消意图决定是否允许结果发布。即使数据库取消失败、Worker 失联或终态同时发布，运行最终也会收敛到唯一且可解释的事实。

**Blocked by:** 04 — 原子发布精确受限的结果快照；05 — 接管失租运行并限制自动执行尝试；07 — 幂等取消排队中的查询运行

**Status:** ready-for-agent

- [ ] 取消 `running` 查询运行先持久化取消意图并进入 `cancelling`，返回 HTTP 202；重复取消 `running` 或 `cancelling` 不产生新意图并返回 HTTP 202。
- [ ] 当前所有者在持久化意图后尽最大努力请求数据库取消；取消请求失败不会撤销意图，之后返回的结果仍被丢弃。
- [ ] 当前所有者在数据库工作结束或取消请求返回后把运行收敛为 `cancelled`；所有者失联时，在租约过期后的一个轮询周期内由协调循环收敛。
- [ ] 取消意图成功记录后不得领取新执行尝试，自动恢复也不能绕过取消。
- [ ] 取消意图先于成功或失败发布时，取消获胜且不保存结果；成功终态和结果先原子发布时，迟到取消返回 HTTP 200 并保留成功事实。
- [ ] `rejected` 或 `failed` 返回 HTTP 409 `query_run_not_cancellable`；已经 `cancelled` 或 `succeeded` 返回 HTTP 200 和既有终态。
- [ ] 工作台可取消运行中的查询，清晰显示 `cancelling` 与 `cancelled`，并持续轮询直至稳定终态。
- [ ] 真实 PostgreSQL 竞态证据覆盖数据库取消成功与失败、Worker 失联、重复取消以及取消和终态发布的两种顺序。
