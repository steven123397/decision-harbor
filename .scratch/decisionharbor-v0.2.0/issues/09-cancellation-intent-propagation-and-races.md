# 09 — 取消意图、取消传播与终态竞态

**What to build:** 用户可以在排队或运行阶段取消查询运行。排队取消使它不再进入 analytics 执行；运行取消尽最大努力停止数据库工作。取消意图一旦被记录就不会被迟到的查询结果覆盖，而已经原子发布的成功事实也不会被迟到的取消改写。取消请求本身可以安全地重复发送。

**Blocked by:** 07

**Status:** ready-for-agent

- [ ] 取消 `queued` 运行直接进入 `cancelled`，且该运行不能被 Worker 领取
- [ ] 取消 `running` 运行先持久化取消意图并进入 `cancelling`，再 best effort 请求数据库取消
- [ ] `cancelling` 运行不得领取新的执行尝试
- [ ] 当前所有者在数据库工作结束或取消请求返回后收敛为 `cancelled`
- [ ] 所有者在 `cancelling` 期间失联时，由接管或清理循环在租约过期后的一个轮询周期内收敛为 `cancelled`
- [ ] 数据库取消失败不撤销取消意图，之后返回的查询结果仍被丢弃
- [ ] 重复取消不制造新状态，也不返回错误
- [ ] 取消与成功或失败发布通过条件更新竞争：取消意图先成功记录时取消获胜并丢弃之后返回的结果
- [ ] 成功终态与结果已原子提交时，迟到的取消只返回既有成功事实，不改写已读取的结果
- [ ] 已经 `cancelled` 或 `succeeded` 的运行收到取消请求时返回 HTTP 200 和既有终态
- [ ] `rejected` 或 `failed` 运行收到取消请求时返回 HTTP 409 `query_run_not_cancellable`
- [ ] 取消 `queued` 返回 HTTP 200，取消 `running` 或 `cancelling` 返回 HTTP 202
- [ ] 取消后不再产生新的执行尝试
