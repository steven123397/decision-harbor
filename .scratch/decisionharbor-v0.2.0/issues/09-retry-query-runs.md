# 09 — 为失败或取消运行创建幂等重试

**What to build:** 让分析用户从执行失败或已取消的运行创建一个关联但独立的新生命周期。重试保留原运行作为审计事实，并再次经过治理边界，而不是复用终态或伪装成自动执行尝试。

**Blocked by:** 02 — 保证提交请求幂等；08 — 取消运行中的查询并裁决终态竞态

**Status:** ready-for-agent

- [ ] `failed` 或 `cancelled` 查询运行可以创建带 `retry_of` 关联的新查询运行，并以 HTTP 202 返回；来源运行及其终态保持不变。
- [ ] 重试使用来源 SQL 并重新经过当前请求校验和策略判定，不能绕过 SQL 治理或 analytics 只读身份；重试运行拥有独立状态、时间和执行尝试。
- [ ] `rejected`、`succeeded`、`received`、`queued`、`running` 和 `cancelling` 返回 HTTP 409 `query_run_not_retryable`，不存在返回 `query_run_not_found`。
- [ ] 重试支持合法 `Idempotency-Key`；相同来源运行与相同键只创建一个重试运行，而相同键可在不同来源运行作用域中独立使用。
- [ ] 显式重试运行与 Worker 自动执行尝试在 API、持久事实和历史展示中保持可区分，不覆盖来源审计。
- [ ] 工作台仅对可重试终态提供重试操作，并在创建后跟踪新的查询运行，同时保留来源关联供用户辨认。
- [ ] 公开 HTTP 与浏览器证据覆盖允许状态、禁止状态、来源关联、幂等重放以及策略重新拒绝。
