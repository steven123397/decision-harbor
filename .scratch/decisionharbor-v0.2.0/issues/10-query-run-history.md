# 10 — 分页恢复查询运行历史

**What to build:** 让分析用户按稳定顺序浏览近期查询运行，并从历史中恢复某次运行及其可用结果。分页在相同创建时间和并发新增运行下仍不会重复或跳过原页面序列。

**Blocked by:** 01 — 打通持久异步查询主链

**Status:** ready-for-agent

- [ ] 历史端点按 `(created_at DESC, id DESC)` 稳定排序，默认返回 20 条，并接受 1 到 100 的 `limit`。
- [ ] 下一页使用服务端生成的不透明游标，并严格位于游标记录之后；相同创建时间由 ID 降序稳定打破平局。
- [ ] 获取游标后新增查询运行，不会使该游标后续页面重复或跳过原快照中的记录。
- [ ] 非法 `limit` 或伪造、损坏、过期格式的游标返回 HTTP 422 `invalid_pagination`，不泄漏内部查询或编码细节。
- [ ] 历史项目提供恢复运行、辨认策略拒绝、执行失败、取消、重试来源和结果可用性所需的稳定审计事实。
- [ ] 工作台支持加载后续页面并选择历史运行，随后通过既有状态与结果端点恢复，而不是重新提交或重新执行 SQL。
- [ ] 真实 PostgreSQL 和浏览器证据覆盖相同时间戳、并发新增、多页边界、非法分页及历史恢复。
