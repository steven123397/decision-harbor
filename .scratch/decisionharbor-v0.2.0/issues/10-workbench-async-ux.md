# 10 — 工作台异步体验完整化

**What to build:** 查询工作台完整呈现异步生命周期：用户看到排队、运行、取消中与终态，页面刷新后按运行标识恢复状态；可对运行取消，并对允许状态执行重试；历史列表按分页合同展示近期运行；策略拒绝、执行失败、取消三种结果清晰区分，用户能采取正确下一步；结果暂不可用与过期有明确反馈。轮询（不引入 SSE 或 WebSocket）在终态、页面卸载和不可恢复错误后停止，同一运行不产生重叠请求；窄视口与键盘操作下保持基本可访问性。工作台不扩展为完整运营前端，也不做独立视觉改版。

## Resolution

**结果：** 交付工作台异步体验完整化：完整异步生命周期呈现、取消/重试操作、分页历史、三种结果反馈与轮询纪律。

- **生命周期呈现与恢复**：`queued`/`running`/`cancelling` 各有独立进度态（附状态说明与「结果未就绪；继续轮询」注记）；终态收敛为 settled 视图。刷新后经 `sessionStorage` 运行标识恢复轮询（restoring 态），终态/不可恢复错误时清除标识；历史面板提供另一条恢复路径——点击任意历史运行即恢复其状态与结果，活动运行随之成为会话运行。
- **取消与重试**：`queued`/`running` 显示 Cancel run，`cancelling` 不再重复提供（API 幂等但无需再请求）；取消响应直接终态时接管轮询令牌立即收敛，返回 `cancelling` 时继续轮询至收敛。Retry run 仅在 `failed`/`cancelled` 呈现；重试产生的新运行立即成为活动运行（写入会话标识、刷新历史），重试 SQL 被策略拒绝时与提交路径对称呈现 rejected 终态；409 动作被拒（`query_run_not_cancellable`/`query_run_not_retryable`）以 `role=alert` 行内反馈。取消/重试经 `runExclusiveAction` 互斥。
- **历史分页**：挂载时加载第一页（服务端默认 limit 20）；`next_cursor` 存在时提供 Load more 追加下一页；新运行创建与运行收敛后自动刷新第一页，另有手动刷新按钮。行内容为状态徽标、时间、行数/错误码、短 ID。
- **结果反馈三分**：未就绪（活动态注记，轮询继续；succeeded 后 `result_not_ready`/瞬时错误同样继续轮询）、不可用（`result_unavailable` 面板）、已过期（`result_expired` 面板）独立呈现；读取永不重新执行 SQL。
- **轮询纪律**：顺序递归轮询 + 令牌失效（终态、卸载、动作接管）；瞬时错误（`service_not_ready`/`audit_unavailable`）按指数退避继续轮询（上限 10× 间隔），其余错误视为不可恢复即停止；无 SSE/WebSocket。
- **可访问性与响应式**：交互全部为原生 button/textarea；e2e 键盘用例覆盖提交（Enter）、取消（Space）、重试（Enter）；窄视口 375px 断言 `documentElement` 无横向溢出（成功、失败、历史三种布局），桌面视口对成功与错误布局同样断言。
- **测试**：单测 33→52（取消 3、重试 5、历史 4、结果反馈 2、轮询错误 2，含既有适配）；e2e 4→10（排队/运行/取消、键盘操作、重试关联、历史打开、过期/不可用、窄视口）。e2e 取消用 4 表笛卡尔积（约 2.4×10⁹ 组合，实测超出 5s 语句超时）制造真实 running 窗口；即使语句超时先于数据库取消返回，取消意图已记录即由取消栅栏裁决，取消获胜。

**实际验证：** `COMPOSE_PROJECT_NAME=zcode-glm-53-xhigh API_HOST_PORT=18003 WEB_HOST_PORT=15176 ./dev test` 全绿——api-test 271 通过、web-test 52 通过、e2e 10 通过，退出码 0；`datasets/sales-analytics-v1` 运行 `python3 validate.py` 通过；`git diff --check` 干净。

**Review 结论：** `/code-review` 双轴复核。Standards 无硬违规；按发现修复四处：`refreshHistory`/`loadMoreHistory` 的响应塑形合并为 `applyHistoryResponse`、取消/重试互斥脚手架抽为 `runExclusiveAction`、`SettledState` 两分支重复的重试块抽为局部 `retryActions`、移除 `listHistory` 未使用的 `limit` 参数并更名 `INITIAL_HISTORY`。两处判断项保留：settled 视图四个可空字段的合法组合未细化为子变体、`finish` 的错误码级联未抽共享映射（改动面大于收益，行为已由单测固定）。Spec：逐条验收核对通过；按发现补齐两处证据缺口（桌面视口溢出断言、纯键盘 e2e 用例），并为瞬时错误轮询增加指数退避（可恢复语义不变，不再以固定 1s 间隔无限打满不可用服务）；一处合同边界记录于保留风险。

**保留风险：**

- 动作接管（打开历史运行、重试、取消直接终态）令牌失效旧轮询时，被废弃循环的在途 GET 与新循环首个 GET 可能在同一运行上短暂并存；过期响应被令牌丢弃、不产生状态影响。字面零重叠需 AbortController 级改造，本版本未做。
- 历史首屏使用服务端默认 limit=20，Load more 仅依赖 `next_cursor`；满页时空页游标为 09 记录的 API 已知边界。
- 非 JSON 响应（如反向代理异常）在提交路径映射为 `service_not_ready` 并使就绪指示转为 Unavailable，就绪重检按钮可恢复。
