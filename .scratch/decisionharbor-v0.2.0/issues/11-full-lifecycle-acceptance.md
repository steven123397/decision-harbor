# 11 — 完成全生命周期与运行环境验收

**What to build:** 让平台维护者能够在干净、隔离且可重启的 Compose 环境中运行完整异步查询产品，并通过统一验证入口证明用户工作流、Worker 恢复、治理边界和固定数据合同共同成立。

**Blocked by:** 02 — 保证提交请求幂等；05 — 接管失租运行并限制自动执行尝试；06 — 过期并幂等清理结果快照；08 — 取消运行中的查询并裁决终态竞态；09 — 为失败或取消运行创建幂等重试；10 — 分页恢复查询运行历史

**Status:** ready-for-agent

- [ ] 干净环境可完成构建、身份建立、迁移、固定数据 seed，并启动就绪的 Web、API、Worker 和 PostgreSQL；重复启动、迁移及 seed 不产生破坏性变化。
- [ ] 默认启动一个 Worker，并能以两个 Worker 副本验证全局容量、接管和发布栅栏；API 或 Worker 重启后，持久查询运行继续恢复而不是被笼统标记失败。
- [ ] Compose 项目名、Web 与 API 宿主端口可配置，多个工作区可以并行运行，不共享固定容器、网络、数据卷或绑定目录。
- [ ] `/health` 只表达 API 进程存活；`/ready` 使用独立最小权限身份检查数据库、迁移和 seed，并在 1 秒截止时间内成功或返回 HTTP 503 `service_not_ready`。
- [ ] 完整浏览器流程覆盖提交、排队、运行、成功结果、策略拒绝、执行失败、取消、重试、历史以及结果未就绪、不可用和过期反馈。
- [ ] 工作台在桌面与窄视口下无内容重叠，键盘可以完成提交、轮询后的取消或重试、历史选择和结果读取，动态状态不会造成不可理解的布局跳动。
- [ ] 回归证据继续证明 AST 默认拒绝、对象与系统目录边界、analytics 真实只读权限、显式结果类型、超时、固定数据口径、seed fail-closed 和错误脱敏。
- [ ] 固定数据校验与统一测试入口通过；任一 API、Worker、Web、浏览器或环境验收失败都会使统一入口非零退出，验证后不留下应提交的缓存、报告或生成物。
