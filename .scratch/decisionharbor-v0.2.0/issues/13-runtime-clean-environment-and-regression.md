# 13 — 运行环境、干净环境验证与回归收口

**What to build:** 干净环境下的一条命令可以重建并验证整套运行环境，包括迁移、重复 seed、Web/API/Worker 就绪、并行 Compose 项目隔离和重启恢复。Worker 可以横向扩展到 2 个副本并共享全局容量上限。统一测试入口在任何失败时返回非零退出码，既有治理与数据口径回归全部保持。

**Blocked by:** 04, 05, 08, 12

**Status:** ready-for-agent

- [ ] 干净环境执行统一入口后，迁移与重复 seed 成功，Web、API 和 Worker 均就绪
- [ ] 重复执行 seed 是无操作；未标记已有行或版本、摘要、行数冲突时以 `seed_conflict` 失败并完整回滚，不自动覆盖
- [ ] 并行 Compose 项目使用可配置的项目名与宿主端口，互不干扰
- [ ] Worker 进程重启后未完成的查询运行被恢复，不永久卡住
- [ ] Compose 可同时运行 2 个 Worker 副本，且共享全局并发上限
- [ ] `/ready` 使用独立最小权限身份检查两个数据库、迁移和 seed 标记，并在 1 秒截止时间内成功或返回 HTTP 503 `service_not_ready`；`/health` 只表达进程存活
- [ ] 固定数据校验在失败时返回非零退出码
- [ ] 统一测试入口在任何测试失败时返回非零退出码
- [ ] 既有回归全部保持：SQL AST 默认拒绝、允许对象范围、系统对象与绕过探针、analytics 真实只读权限、固定数据契约与业务口径、查询超时与行数限制
- [ ] 异步路径继续使用 AST 策略与 analytics 只读身份，排队与恢复没有成为治理绕过路径
