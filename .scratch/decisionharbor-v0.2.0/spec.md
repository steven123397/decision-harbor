# DecisionHarbor v0.2.0：可恢复的异步查询运行

**Status:** resolved

## Problem Statement

DecisionHarbor 当前在一次 HTTP 请求内完成策略校验、SQL 执行和结果返回。长查询会占用请求生命周期；进程重启会把未完成运行直接收敛为失败；用户无法在刷新后读取结果，也不能取消、重试或查看历史运行。系统还不能在多个执行者之间协调容量、恢复失去所有权的任务，或阻止过期执行者发布终态。

用户需要一条仍受既有 SQL 治理保护、但可以持久排队、独立执行、轮询恢复并清晰处理取消和故障的查询链路。

## Solution

提交 API 同步完成请求校验和 SQL 策略判定。被拒绝的查询立即形成 `rejected` 运行；被允许的查询持久化为 `queued` 并以 HTTP 202 返回。独立 Worker 从 PostgreSQL 持久队列领取查询，使用 analytics 只读身份执行，并通过租约、心跳、执行尝试和 generation fencing 协调多个副本。

客户端轮询查询运行和有限结果快照。用户可以取消排队或运行中的查询，为失败或已取消的查询创建关联的重试运行，并查看分页历史。系统以条件更新决定取消与终态发布的竞态，以原子事务保存成功终态和结果快照，以保留期和幂等清理控制存储。

## User Stories

1. 作为分析用户，我希望提交合法 SQL 后立即获得查询运行标识，以便不必保持一个长时间 HTTP 请求。
2. 作为分析用户，我希望策略拒绝在提交阶段立即返回，以便快速修改 SQL，而不等待队列处理。
3. 作为分析用户，我希望重复发送同一幂等请求时得到同一查询运行，以便网络重试不会创建重复工作。
4. 作为分析用户，我希望相同幂等键与不同 SQL 产生稳定冲突，以便发现客户端错误而不是静默复用错误运行。
5. 作为分析用户，我希望看到查询处于排队、运行、取消中或终态，以便理解系统正在做什么。
6. 作为分析用户，我希望页面刷新后仍能按运行标识恢复状态，以便浏览器会话不是查询生命周期的所有者。
7. 作为分析用户，我希望读取成功查询的列、行和截断信息，以便继续分析有限结果。
8. 作为分析用户，我希望未完成结果返回明确的暂不可用语义，以便客户端知道应继续轮询。
9. 作为分析用户，我希望结果过期时收到明确的过期语义，以便不会误以为查询失败或不存在。
10. 作为分析用户，我希望取消仍在排队的查询，以便它不会进入 analytics 执行。
11. 作为分析用户，我希望取消正在运行的查询，以便系统尽最大努力停止数据库工作并阻止结果发布。
12. 作为分析用户，我希望重复取消不会制造新状态或错误，以便客户端可以安全重试取消请求。
13. 作为分析用户，我希望取消请求在终态发布前被记录时取消获胜，以便之后完成的数据库查询不会覆盖我的意图。
14. 作为分析用户，我希望已经成功发布的运行保持成功，以便迟到的取消不能改写已读取结果。
15. 作为分析用户，我希望为失败或已取消运行创建新的重试运行，以便保留原始审计事实和新的执行生命周期。
16. 作为分析用户，我希望策略拒绝必须修改 SQL 后重新提交，以便重试操作不能绕过治理判断。
17. 作为分析用户，我希望成功运行不可重试，以便不会无意重复昂贵查询。
18. 作为分析用户，我希望查看按创建时间分页的运行历史，以便恢复近期分析工作。
19. 作为分析用户，我希望查询工作台清晰区分策略拒绝、执行失败和取消，以便采取正确的下一步。
20. 作为分析用户，我希望窄视口和键盘操作下仍能提交、轮询、取消、重试和读取结果，以便工作台保持基本可访问性。
21. 作为平台维护者，我希望两个 Worker 副本共享全局并发上限，以便横向扩展不会突破数据库容量。
22. 作为平台维护者，我希望 Worker 定期续租并在租约过期后由其他副本接管，以便进程崩溃不会永久卡住查询。
23. 作为平台维护者，我希望旧执行尝试不能发布状态或结果，以便接管后的新所有者不被迟到写入覆盖。
24. 作为平台维护者，我希望基础设施故障最多触发 3 次自动执行尝试，以便临时故障可恢复且永久故障不会无限循环。
25. 作为平台维护者，我希望非法 Worker 配置在启动时失败，以便错误的租约、心跳或容量参数不会进入运行期。
26. 作为平台维护者，我希望结果快照受行数、字节数和保留期限制，以便平台数据库成本可预测。
27. 作为平台维护者，我希望结果清理可以重复执行，以便调度重叠或进程重启不会破坏状态。
28. 作为安全负责人，我希望异步路径继续使用 AST 策略和 analytics 只读身份，以便排队与恢复不能成为治理绕过路径。
29. 作为安全负责人，我希望 API 不持有执行用户 SQL 所需的 analytics 查询凭据，以便 HTTP 层不能越过 Worker 边界。
30. 作为审计人员，我希望每次查询运行、执行尝试、取消和重试都有稳定关联与时间事实，以便重建一次查询的生命周期。

## Implementation Decisions

- v0.2.0 有意把提交合同从同步成功响应改为异步 HTTP 202；成功结果不再随提交响应即时返回。
- 状态集合为 `received`、`rejected`、`queued`、`running`、`succeeded`、`failed`、`cancelling` 和 `cancelled`。`rejected`、`succeeded`、`failed` 和 `cancelled` 是不可逆终态。
- API 在入队前同步执行请求校验、SQL AST 策略和对象范围校验。策略允许时完成 `received → queued`，策略拒绝时完成 `received → rejected` 并返回 HTTP 422。
- 队列使用 platform PostgreSQL 持久记录，不引入 Redis 或外部消息中间件。默认运行 1 个 Worker，并必须支持 2 个 Worker 副本。
- API 只持有 platform 凭据和独立的最小就绪探测凭据。Worker 持有 platform 任务凭据与 analytics 查询凭据；只有 Worker 执行用户 SQL。
- 全部 Worker 共享数据库协调的全局并发上限，默认值为 4。该上限统计当前 generation 且租约未过期的有效执行所有权，不统计已经失租但尚未物理停止的旧数据库活动；容量不能只由单进程内计数控制。
- 每次领取产生包含 Worker 标识和递增 generation 的执行尝试。Worker 通过租约和心跳维持所有权；租约过期后其他 Worker 可以接管。查询运行在接管期间保持 `running`，不回退到 `queued`。
- 任何状态或结果发布都必须核对当前运行状态、执行尝试和 generation。旧 generation 的写入不产生效果。
- 自动执行尝试只用于未产生终态的租约丢失，以及当前所有者遇到 `analytics_unavailable`（连接或会话中断）；Worker 进程失联通过租约丢失进入同一路径。`query_timeout`、`query_semantic_error`、`result_too_large`、`unsupported_result_type` 和 `internal_error` 直接进入 `failed`，不自动尝试。每个运行最多 3 次执行尝试；自动尝试不能改变 SQL、绕过策略或覆盖取消，尝试耗尽后运行进入稳定的 `failed` 终态。
- 默认配置键为：`QUERY_MAX_CONCURRENCY=4`、`WORKER_LEASE_MS=15000`、`WORKER_HEARTBEAT_MS=3000`、`WORKER_POLL_MS=250`、`WORKER_MAX_EXECUTION_ATTEMPTS=3`。各值必须是正整数，心跳必须严格小于租约；非法配置使对应进程非零退出。实现可以额外记录并验证合理上界，评分不绑定本 spec 未列出的阈值。
- 排队运行的取消直接进入 `cancelled`，且不能被 Worker 领取。运行中的取消先持久化取消意图并进入 `cancelling`，再 best effort 请求数据库取消。
- `cancelling` 不是可无限停留的状态。取消意图持久化后不得领取新尝试；当前所有者在数据库工作结束或取消请求返回后收敛为 `cancelled`，所有者失联时由接管/清理循环在租约过期后的一个轮询周期内收敛为 `cancelled`。数据库取消失败不撤销取消意图，之后返回的结果仍被丢弃。
- 取消与成功/失败发布通过条件更新竞争。如果取消意图先成功记录，取消获胜并丢弃之后返回的查询结果；如果成功终态和结果已原子提交，迟到取消只返回既有成功事实。
- 提交与重试通过 `Idempotency-Key` 请求头支持幂等，键为 1 到 128 个可见 ASCII 字符。未提供键时每次请求创建新运行。当前版本没有用户或租户，提交键在整个产品实例内生效；重试键按来源运行 ID 隔离。相同作用域、相同键和完全相同的输入返回原运行；同键不同输入返回 HTTP 409 `idempotency_conflict`。取消接口本身幂等。
- 只有 `failed` 和 `cancelled` 可以重试。重试创建新的查询运行并记录 `retry_of`；`rejected` 必须修改后重新提交，`succeeded` 不可重试。
- 成功终态与结果快照在一个 platform 事务中原子保存。快照最多 500 行和 1 MiB，保留数据库返回顺序的结果前缀并记录 `truncated`。
- 1 MiB 等于 1,048,576 字节，按 `{"columns":[...],"rows":[...]}` 的紧凑 UTF-8 JSON 计算：键顺序固定为 `columns`、`rows`；每个列对象固定为 `{"name":string,"type":string}` 并使用该字段顺序；每行是与列位置对应的 JSON 数组。分隔符不含空格，非 ASCII 字符直接编码为 UTF-8。envelope、运行元数据和 `truncated` 不计入该预算。
- 列定义本身超过 1 MiB、第一行加入后使快照超过 1 MiB，或任意单行的 JSON 数组本身超过 1 MiB 时，运行进入 `failed`，错误码为 `result_too_large`，不保存部分行或部分单元格。其他累计越界只保存不超过行数和字节数双重边界的最长前缀，并记录 `truncated`。
- 结果值沿用 [ADR-0007](../../docs/adr/0007-preserve-result-values-with-explicit-json-types.md)：`bigint` 与 `numeric` 是十进制字符串，日期与时间戳是 ISO 8601 字符串，布尔值、32 位整数、文本与 `null` 使用 JSON 原生类型；未知类型以 `unsupported_result_type` 失败。
- 结果保留 24 小时，以数据库记录的 `finished_at + 24h` 为准。清理操作幂等，并只删除结果内容，不删除长期审计事实。
- 结果尚未就绪返回 HTTP 409；结果已过期返回 HTTP 410；运行存在但结果不可用返回 HTTP 409。结果读取永远不重新执行 SQL。
- 外部 API 使用下节定义的路径、状态码和分页合同。所有端点沿用统一 `{data, error}` envelope 和稳定错误码；错误响应不得包含数据库原始消息、堆栈、DSN、凭据或内部 SQL。
- Web 使用轮询，不引入 SSE 或 WebSocket。轮询必须在终态、卸载和不可恢复错误后停止，并避免同一运行的重叠请求。
- 工作台可以改善信息层级、响应式和可访问性，但不扩展为完整运营前端或独立视觉改版。

## External HTTP Contract

| 方法 | 路径 | 成功合同 |
| --- | --- | --- |
| `POST` | `/api/v1/query-runs` | 请求体为 `{ "sql": string }`。策略允许的首次请求或幂等重放返回 HTTP 202 和运行；策略拒绝的首次请求或幂等重放均返回 HTTP 422 和原 `rejected` 运行。 |
| `GET` | `/api/v1/query-runs/{id}` | 存在时返回 HTTP 200 和运行事实；不存在返回 HTTP 404 `query_run_not_found`。 |
| `GET` | `/api/v1/query-runs/{id}/result` | 快照可读时返回 HTTP 200；未完成返回 HTTP 409 `result_not_ready`；终态但没有可读快照返回 HTTP 409 `result_unavailable`；已过期返回 HTTP 410 `result_expired`。 |
| `POST` | `/api/v1/query-runs/{id}/cancel` | `queued` 直接取消并返回 HTTP 200；`running` 或 `cancelling` 返回 HTTP 202；已经 `cancelled` 或 `succeeded` 返回 HTTP 200 和既有终态；`rejected` 或 `failed` 返回 HTTP 409 `query_run_not_cancellable`。 |
| `POST` | `/api/v1/query-runs/{id}/retry` | `failed` 或 `cancelled` 创建关联运行并返回 HTTP 202；幂等重放返回同一新运行和 HTTP 202；其他状态返回 HTTP 409 `query_run_not_retryable`。 |
| `GET` | `/api/v1/query-runs` | 返回 HTTP 200 和分页历史。`limit` 默认 20、范围 1 到 100；`cursor` 是服务端生成的不透明字符串。 |

历史按 `(created_at DESC, id DESC)` 稳定排序。下一页严格位于游标记录之后；相同创建时间以 ID 降序打破平局，新插入运行不会使已取得游标的后续页面重复或跳过原快照中的记录。无效 `limit` 或 `cursor` 返回 HTTP 422 `invalid_pagination`；不合法的 `Idempotency-Key` 返回 HTTP 422 `invalid_idempotency_key`。

## Preserved Baseline Contracts

- SQL AST 默认拒绝、对象允许范围和 analytics 数据库只读权限继续共同生效；异步化不能扩大允许的 SQL、对象、函数或类型转换。
- 查询结果继续通过服务端游标有界提取。执行路径不得先完整物化再截断；任何成功、失败、取消或失租路径都必须关闭游标并结束事务，使连接返回可复用状态。
- 固定数据 seed 遵循 [ADR-0008](../../docs/adr/0008-fail-closed-when-seeding-fixed-data.md)：匹配时重复执行是无操作，未标记已有行或版本、摘要、行数冲突时以 `seed_conflict` 失败并完整回滚，不自动覆盖。
- `/ready` 使用独立最小权限身份检查两个数据库、迁移和 seed 标记，并在 1 秒截止时间内成功或返回 HTTP 503 `service_not_ready`；`/health` 只表达进程存活。
- 所有已知失败映射为稳定、脱敏的错误码和摘要；未知异常统一收敛为 `internal_error`，不得向外部响应或默认日志泄漏数据库原始错误、堆栈、DSN、凭据或原始 SQL。
- 固定销售数据契约、业务口径、并行 Compose 项目隔离和统一非零测试失败语义保持不变。

## Testing Decisions

- 主要验收接缝是完整 Compose 环境中的公开 HTTP API 和浏览器工作台。测试只判断可观察状态、响应、持久事实和用户行为，不依赖私有方法调用次数。
- 基于 PostgreSQL 的 Worker 集成接缝用于稳定构造双 Worker、租约过期、接管、旧 generation、全局容量和取消竞态；这些测试使用真实数据库事务与约束，不以 Mock 代替。
- 纯状态决策、配置边界和结果大小计算可以使用快速单元测试，但不能用单元测试代替端到端生命周期证据。
- 提交合同测试覆盖 202、同步 422、幂等复用、同键冲突和统一错误 envelope。
- 生命周期测试覆盖合法迁移、非法迁移、不可逆终态和接管时不回退运行状态。
- 并发测试同时运行 2 个 Worker，证明数据库中未过期的有效执行所有权从不超过 4，并证明每个运行从不出现两个可发布所有者。测试不把已经失租的旧数据库活动计为有效所有权。
- 恢复测试在领取后、查询执行中和终态发布前终止 Worker，证明租约接管、尝试上限和旧 generation fencing；另证明 `analytics_unavailable` 自动尝试，而查询超时、语义错误、结果过大、未知结果类型和内部错误直接失败。
- 取消测试覆盖 queued 取消、running 取消、重复取消、数据库取消失败、`cancelling` 时 Worker 失联，以及取消与 succeeded/failed 发布的两种竞态顺序；每条路径最终进入稳定终态且取消后没有新执行尝试。
- 结果测试覆盖 500 行边界、完整快照恰好 1 MiB 与超出 1 字节、列定义过大、首行和后续行单独过大、多字节 UTF-8、稳定前缀截断、显式类型序列化、成功原子发布、24 小时过期和重复清理。
- 重试测试覆盖允许状态、禁止状态、`retry_of`、重试幂等和取消不被自动尝试绕过。
- 回归测试继续证明 SQL AST 默认拒绝、允许对象范围、系统对象和绕过探针、analytics 真实只读权限、固定数据口径、超时与行数限制。
- 浏览器测试覆盖提交、排队、运行、成功结果、策略拒绝、执行失败、取消、重试、历史和过期/不可用反馈，并检查桌面与窄视口无内容重叠。
- 干净环境验证覆盖迁移、重复 seed、Web、API 和 Worker 就绪、并行 Compose 项目隔离和重启恢复。统一测试入口失败时必须返回非零退出码。

## Out of Scope

- LLM、自然语言转 SQL、RAG、MCP、A2A 或语义层。
- 认证、用户、租户、复杂 RBAC、主体级历史隔离或公网生产部署。
- Redis、外部消息队列、SSE、WebSocket 或流式结果。
- 查询优先级、定时任务、批处理、保存查询、结果导出、图表和完整运营后台。
- 多区域高可用、严格物理 exactly-once 或跨数据库分布式事务。
- 修改固定销售数据契约、业务口径或既有 SQL 治理允许范围。
- 将独立视觉质量作为本版本交付目标。

## Further Notes

- 当前同步实现是迁移起点和回归基线，不要求保持同步 POST 成功响应的向后兼容。
- PostgreSQL 队列、执行所有权与结果快照的长期取舍分别记录在 [ADR-0003](../../docs/adr/0003-use-postgresql-as-the-durable-query-queue.md)、[ADR-0005](../../docs/adr/0005-coordinate-valid-execution-ownership.md) 和 [ADR-0004](../../docs/adr/0004-store-bounded-result-snapshots.md)；spec 只规定本版本必须交付的外部行为和实现约束。
- 路线已经足够清晰，不需要为本功能建立 Wayfinder map。spec 评审通过后，再由 `/to-tickets` 生成实现使用的 tracer-bullet tickets。
