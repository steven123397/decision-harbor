# 文档目录规则

## 适用范围与优先级

- 本文件适用于 `docs/` 及其子目录，补充根目录 `AGENTS.md` 的项目级规则。
- 更深层目录可以在确有独立边界时增加规则，但不得复制根规则或本文件全文。

## 文档职责

- `background/` 是外部输入和已确认约束的事实来源，包括产品需求、技术约束和数据契约相关说明。
- `design/` 是长期有效的产品内生设计，记录边界、术语、接口、数据不变量和关键决策。
- `plan/` 是阶段工作安排，记录目标、任务切片、依赖、验证和交付边界。
- `status/` 是当前项目快照，记录结论、进展、风险和下一步。
- `index.md` 只负责导航、阅读顺序和职责说明，不复制其他文档正文。

同一事实只在一个正式文档中维护。需要跨目录引用时使用相对链接，并在事实变化时更新其权威来源和受影响的导航。

## 维护规则

- 背景资料只有在产品或技术约束发生正式变化时才更新；不要用实现结果反向迁就背景口径。
- 设计文档记录已作出的长期决策；尚未收敛的选项放入相关计划或状态文档，不伪装成设计结论。
- 计划文档在阶段结束后保留交付边界和验证结果；当前事实和风险写入 `status/`，不在多个目录重复。
- 状态文档保持短小并反映当前事实；详细理由链接到设计或计划文档。
- 新增正式文档后同步更新 `docs/index.md`，删除或移动文档时检查所有反向链接。
- 不创建空的专题文档、ADR 或额外治理元文件；只有存在真实内容和稳定维护责任时才拆分文件。
