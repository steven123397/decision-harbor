# docs 子树规则

适用于 `docs/` 整个子树，补充根 `AGENTS.md`；冲突时以本文件为准。

## 目录职责

- `background/`：外部输入、需求背景与约束来源。内容由产品方确认，实现过程中不得改写以迁就实现；确有修订走产品确认流程。
- `design/`：长期边界、领域模型、接口、数据与关键决策。描述稳定事实，不记进度。
- `plan/`：阶段目标、任务切片、依赖、验证与交付边界。阶段完成后归档或标注完成状态。
- `status/`：当前事实、进展、风险与下一步。只维护当前结论，随事实更新。
- `index.md`：只负责导航和阅读入口，不复制正文。

## 写作规则

- 同一事实只在一个角色目录维护；其他位置引用链接，不复制内容。
- 新增、重命名或删除正式文档时，同步更新 `docs/index.md`。
- 模板见各目录 `README.md`；没有真实内容时不要批量生成专题文档。
- 文档使用中文，遵循仓库既有的中文排版与术语习惯。
