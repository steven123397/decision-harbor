# docs/ 写作规则

适用于 `docs/` 全部内容。与根 `AGENTS.md` 冲突时，本文件在文档写作范围内优先。

## 目录职责

| 目录 | 职责 | 不承担 |
| --- | --- | --- |
| `background/` | 已确认的外部输入：产品需求、技术约束 | 设计决策、进度、计划 |
| `design/` | 长期设计事实：边界、领域模型、接口、数据、关键决策 | 阶段任务、当前进度 |
| `plan/` | 阶段目标、任务切片、依赖、验证与交付边界 | 长期设计正文、执行流水账 |
| `status/` | 当前结论、进展、风险和下一步 | 历史叙事、设计与计划正文 |

## 单一事实来源

- 每个事实只在一个文档维护，其他位置用链接引用，不复制正文。
- `background/` 与 `datasets/sales-analytics-v1/` 是需求与数据口径的权威来源；design 文档引用它们，不重述公式与字段清单。
- `index.md` 只做导航。新增、移动或删除正式文档时必须同步更新 `index.md`。

## 修改边界

- `background/` 视为只读；仅在用户明确确认需求或约束变化时修改。
- design 记录仍然成立的决策；决策被推翻时就地更新并注明取代关系，不靠追加新段落堆叠。
- status 只保留当前有效内容：过期结论直接删除或改写，不追加"最新进展"式流水账；相对时间一律写成绝对日期。

## 排版约定

- 中文为主，专有名词、代码与标识符保留英文原文并使用代码标记。
- 中英文、中文与数字之间留一个空格；标点使用全角，代码与路径内除外。
