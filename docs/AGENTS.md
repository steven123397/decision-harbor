# docs 目录规则

本文件管理 `docs/` 下全部正式文档的职责与维护规则。根 `AGENTS.md` 管理仓库级规则；在 `docs/` 范围内，本文件优先于根规则。

## 目录职责

- `background/`：已确认的外部输入，包括产品需求、技术约束和来源背景。只有在用户确认变更意图后才修改；不得改写背景约束来迁就实现。
- `design/`：长期稳定的设计决策，覆盖范围、目标与非目标、领域术语、不变量、模块边界、接口与数据设计、关键取舍、失败与迁移策略、测试接缝和延后决策。角色与模板见 [design/README.md](design/README.md)。
- `plan/`：阶段计划，覆盖阶段目标、未规划区、垂直任务切片、依赖和分层验证。角色与模板见 [plan/README.md](plan/README.md)。
- `status/`：当前事实，只维护结论、进展、风险和下一步，不保留历史流水。维护规则见 [status/README.md](status/README.md)。

## 写入与维护规则

- 同一事实只在一个正式文档中维护；其他位置用链接指向，不在 [index.md](index.md) 或其他文档复制正文。
- 新增正式文档时，必须同步更新 [index.md](index.md)，保证索引能找到全部正式文档。
- 不要在 `docs/` 下建立本文件未定义职责的新目录或平行事实源；确需新角色时，先修订本文件。
- 长期生效的决策以 `design/` 为权威位置；`status/` 只记录「当前处于什么状态」。
- 需要同步更新文档的变更范围（API、数据库、查询策略、运行环境）以根 `AGENTS.md` 为准。
