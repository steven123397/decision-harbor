# DecisionHarbor 文档工作规则

## 作用域

本文件适用于 `docs/` 子树，并补充仓库根 `AGENTS.md`。两者同时生效；冲突时以本文件为准。

## 阅读顺序

进入文档工作时，先阅读 `docs/index.md`，再依次读取相关的 `background/`、`status/`、`design/` 和 `plan/` 文档。涉及固定分析数据时，还必须读取 `datasets/sales-analytics-v1/README.md` 与 `contract.json`。

## 目录边界

- `background/`：外部输入、已确认需求和技术约束。实现困难不是修改背景事实的理由。
- `design/`：长期边界、领域模型、接口、数据设计和关键决策。设计必须能追溯到背景输入。
- `plan/`：阶段目标、垂直任务、依赖、验证和交付边界。计划引用设计，不在任务清单中暗改设计。
- `status/`：当前结论、进展、风险和下一步。过期事实应更新或删除，不在此沉淀长期规则。
- `index.md`：正式文档的导航入口。只写链接、阅读顺序和简短职责，不复制正文。

## 维护规则

- 新增、移动、归档或删除正式文档时，同步更新 `docs/index.md` 及受影响的交叉链接。
- 背景输入发生变化时，先记录来源与确认结果，再评估对 design、plan 和 status 的影响。
- 已确认的跨模块决策写入 design；可执行工作写入 plan；实际进度和风险写入 status，避免同一事实多处维护。
- 使用各目录 `README.md` 中的最小模板，但不为尚未确认的主题批量创建空文档。
- 文档中的命令、路径和验证结果必须来自仓库实际内容。修改后检查链接和索引覆盖，并运行 `git diff --check`。
