# 文档规则

本文件只约束 `docs/` 内文档的职责、写入位置和读取边界。仓库级协作规则见根 `AGENTS.md`。

## 目录职责

- `background/`：已确认的外部输入、产品需求和技术约束。实现不得改写这些约束来迁就代码。
- `design/`：长期有效的边界、领域模型、接口、数据与关键决策。新增专题使用 `design/README.md` 中的模板；没有真实决策时不要占位。
- `plan/`：阶段目标、任务切片、依赖、验证和交付边界。新增计划使用 `plan/README.md` 中的模板；未规划内容留在未规划区，不要写成伪计划。
- `status/`：当前事实、进展、风险和下一步。只维护仍有效的结论。
- `index.md`：导航和阅读入口。只链到正式文档，不复制正文。

同一事实只保留一个权威来源。其他位置使用链接，不平行复述。

## 读取边界

恢复项目状态时先读 `index.md` 与 `status/project_status.md`，再按任务需要进入 `plan/`、`design/` 和 `background/`。不要默认遍历整个 `docs/`。

## 不要写入这里的内容

- 数据契约字段与业务口径：以 `datasets/sales-analytics-v1/contract.json` 为准。
- 当前进度：只写在 `status/`，不要写进 `background/` 或根 `AGENTS.md`。
- 长期决策：写在 `design/`，不要只留在 `status/` 或聊天记录。
- 阶段切片与验证门禁：写在 `plan/`，不要把待办清单写进规则文件。
