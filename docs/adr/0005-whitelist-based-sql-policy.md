# SQL 策略采用全维度白名单，而不是黑名单

背景约束要求「基于 AST 与对象访问范围，不能只依赖字符串黑名单」。实现进一步把所有判定维度做成白名单：根节点必须是查询表达式（`SELECT` 或集合操作）、函数调用白名单、CAST 目标类型白名单、全树支持节点白名单、未限定表名必须命中契约五表白名单。白名单之外一律拒绝（`QY_FORBIDDEN_*` / `QY_UNSUPPORTED_SQL`）——新语法与未知路径默认不可用，而非默认放行。`query_to_xml`、`current_user`、`dblink` 等逃逸路径函数天然不在名单内。

策略是纯函数：不访问数据库、不改写 SQL；原文交执行器并落审计。策略检查是第一道边界，不单独承担安全责任——数据库只读身份是第二道。

## 被否方案

- 枚举危险语句 / 函数的黑名单：永远慢于绕过手段的发明速度。
