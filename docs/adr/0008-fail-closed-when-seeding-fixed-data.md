# 固定数据 seed 遇到未知状态时失败

## Context

固定销售数据既是产品输入，也是候选评测的共同基准。重复初始化需要幂等，但已有业务行、缺失标记或摘要不匹配时，自动覆盖会销毁无法判定来源的数据，自动沿用则会让不同工作区基于不同输入运行。

## Decision

seed 只在目标表为空且没有标记时首次载入，或在数据版本、摘要、行数和标记全部匹配时作为无操作成功。任何未标记已有行或合同不一致都以 `seed_conflict` 失败并回滚；正常启动流程不截断、不覆盖，也不猜测性修复固定数据。

## Considered options

- 每次启动先清空再载入：拒绝。它会把普通启动变成隐式破坏性操作，并掩盖输入漂移。
- 标记缺失时信任已有行：拒绝。行数相同也不能证明内容与固定合同一致。
- 冲突时自动修补差异：拒绝。修补规则本身会形成第二套未受版本控制的数据源。

## Consequences

初始化冲突需要维护者显式调查或销毁当前隔离实例后重建，但评测输入不会被静默改变。并发 seed 必须串行化，验证与标记写入必须和数据载入处于同一事务。

## Implementation and evidence

提交 `6e3964f` 实现单事务 seed、数据集摘要与行数验证、并发协调和冲突回滚；`test_seed.py` 覆盖首次载入、重复无操作、标记冲突与未标记已有行。

## Revisit when

固定数据发布新版本或需要保留用户产生的 analytics 数据时，为版本升级单独设计迁移，不放宽当前 fail-closed 合同。
