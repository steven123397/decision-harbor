# 达到行数上限即截断标记，而不是整单失败

达到行数上限即停止取数：响应 `truncated: true`，`row_count` 等于实际返回行数，审计记录同步标记。业务用户拿到带显式截断标记的部分结果，优于整单失败；固定数据集下大结果集（如全量明细）是合理场景，截断标记保证它不会被误读为完整结果。语句超时同理是执行侧失败（`QY_TIMEOUT`）。

## v0.2.0 收紧（#13 扩展）

行数与字节上限统一为取数与快照的共同约束（规格 #6）：

- `QUERY_MAX_ROWS` 默认改为 500，且配置层钳制不得超过 500——500 行是硬上限，不开放上调。
- 1 MiB（`SNAPSHOT_MAX_BYTES`）并行约束：执行器逐行累积序列化字节，行数或字节任一达限即停止取数并标记 `truncated`；同样不开放上调配置。
- 单行自身序列化超过 1 MiB 以稳定错误 `QY_ROW_TOO_LARGE` 落 failed 终态——不在自动重跑集合（ADR-0019），确定性失败直接终态；截断只适用于「多行累计超限」，单行超限不存在有意义的部分结果。
- 字节口径唯一实现（executor `_json`）：取数期的增量累积与 `build_snapshot` 的最终序列化同源，保证「取数时判不超限」与「落库时确实不超限」一致。

## 被否方案

- 超限即报错：用户什么也拿不到，且固定数据下全量查询是正当需求。
- 字节上限开放配置：行数已钳制，字节上限的意义是防单条快照失控；放大它只会把失控转嫁给 platform 库存储与 Web 渲染。
- 单行超限也截断：截断一行内部的数据等于返回损坏的数据，用户无从判断；明确失败优于静默的部分字符串。
