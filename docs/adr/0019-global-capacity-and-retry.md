# 全局并发闸门、attempt 硬上界与基础设施类自动重跑

## 决策

规格 #6 的「容量与重试策略」三项在此固化（实现自由内的选择）：

- **全局并发 4，认领事务内闸门**：`claim_next` 先取事务级 advisory
  lock（`pg_advisory_xact_lock`）串行化「数有效租约 + 认领」临界区，
  有效租约数（`running` 且 `lease_expires_at > now()`）达到
  `GLOBAL_QUERY_CONCURRENCY` 即本轮不认领——第 5 个运行留在 queued
  排队等待，不是失败。容量判定只读 platform 库事实，2 个（或 N 个）
  Worker 实例天然一致，无进程内信号量。
- **attempt 硬上界 3，认领侧统一计数**：attempt 只在认领时递增，
  判据统一为「generation ≥ 1」——首次认领（generation=0）保持
  attempt=1，此后接管与失败回队重跑都递增；候选行过滤
  `attempt < 3`，第 4 次执行在认领入口即不存在。租约过期且耗尽的
  running 行没有认领路径可走，由 keeper 周期清扫
  （`fail_expired_exhausted`）以 `QY_ATTEMPTS_EXHAUSTED` 转入 failed；
  清扫带一个租约周期量级的宽限——刚过期不扫，给「执行者活着、续期
  抖动」的运行留复活窗口（成功发布即离开 running，清扫自然不命中）。
- **自动重跑按错误码分类**：执行失败经 `requeue_or_fail` 处置——
  错误码属 `REQUEUE_ELIGIBLE_ERROR_CODES`（`QY_TIMEOUT`、
  `QY_ANALYTICS_UNAVAILABLE`，即语句超时与连接类失败）且 attempt 未
  耗尽时 CAS 回 queued（清空租约、保留 attempt，重跑在认领时才递增）；
  数据库确定性错误（`QY_EXECUTION_ERROR`）与其他未知异常直接 failed，
  保留最后一次真实错误码。系统动作统一称「自动重跑」以避开「重试」
  ——后者专指用户动作（CONTEXT.md「重试关系」），手动 retry 不在此
  路径内（ADR-0018 的 retry 端点另案）。执行者崩溃接管的重跑由租约
  过期自然驱动，不经错误码判定。

支撑结构：worker 从串行单槽改为并发多槽（执行线程池 +
`WORKER_MAX_CONCURRENCY`，本地只读池同容量），认领时排除自己在执行
的运行（自接管排除——ADR-0017 预告的进程内排除）；keeper 对多条
活动租约逐一续期。

## 理由

- **数据库是唯一事实源是规格硬约束**：任何进程内信号量都只能管住
  单实例；数有效租约把「正在执行的运行」直接落到可观察的行级事实上，
  崩溃、接管、多实例全部自动正确——租约过期即释放容量。
- **advisory lock 只串行化临界区**：不串行就会竞态超限（两个执行者
  同时数到 3、各自认领）。事务级锁在提交/回滚时自动释放，无泄漏
  面积；它不承载所有权语义——所有权仍是租约 + generation
  （ADR-0017 否决的是用 advisory lock 表达所有权，本决策不触碰）。
- **attempt 在认领侧递增**：接管与回队重跑在数据面无法区分（都是
  「queued/过期行被再次认领」，generation 都 ≥ 1），统一按
  generation 判定使任何故障序列下的计数都不可能漏；也保证用户看到
  的 attempt 恒等于真实执行次数。
- **回队保留 attempt、认领时递增**：attempt 字段始终表示「正在/已经
  发生的执行次数」，不会出现「attempt=3 却只执行过 2 次」的中间值。
- **按错误码而非异常类型分类**：错误码是终态发布的稳定事实（审计
  可见），分类判据落在同一口径上，执行器只需把连接类失败
  （`psycopg.OperationalError`，QueryCanceled 除外）映射为
  `QY_ANALYTICS_UNAVAILABLE` 即可；确定性错误重跑必然复现，立即
  failed 也符合用户故事 20（立刻看到失败原因）。
- **清扫带宽限**：耗尽行只剩「执行者已死」与「续期抖动」两种可能，
  立即清扫会误杀后者；宽限一个租约周期后仍无发布，前者几乎是唯一
  解释。误杀的残余面（宽限整段都没续上、恰好又在窗口内跑完）由
  generation fencing 兜底——被误扫的运行其成功发布会被 CAS 拒绝，
  不产生重复终态。

## 被否方案

- **进程内信号量 / 信号量 + 数据库双写**：跨实例不生效或引入两套
  事实源；规格明确「以数据库为唯一事实源」。
- **只数租约不加锁**：并发认领会双双通过容量检查，突破上限（本版
  集成测试以 8 并发认领恰好 4 成功锁定该行为）。
- **回队时预递增 attempt**：会与接管路径的递增叠加产生双重计数，
  且 queued 行的 attempt 不再对应真实执行次数。
- **耗尽行在认领时顺手转 failed**：认领事务持有 advisory lock，
  清扫写放大与容量判定混在同一临界区；独立清扫幂等且通常 0 行。
- **续期被拒即移出排除集合**：旧执行线程仍压着该运行时把它移出
  排除集合，本进程会立刻重新认领它并与自己的旧执行竞态；排除必须
  保持到执行线程收尾。

## 与其他 ADR / 工单的关系

- ADR-0007 的容量语义（单进程信号量）自本决策起被跨实例闸门取代；
  游标与有界池部分继续有效。
- ADR-0017 预告的「worker 并发持有多个认领 + 自接管排除」在此落地；
  租约、接管与 fencing 语义不变。
- #11 的验收（第 5 个排队、总执行 ≤ 3、infra 自动重跑 / 确定性直败、
  v0.1.0 回归通过）由 `tests/integration/test_capacity_and_retry.py`
  与 `tests/unit/test_executor_classification.py` 锁定。
- 「单行超过 1 MiB 立即 failed」属结果快照上限语义（#8 后续的取数
  上限工单），不在 #11 范围；本决策的分类机制已为其预留确定性直败
  路径。
