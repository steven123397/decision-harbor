# 领域文档

工程技能在探索本仓库时应如何消费领域文档。

## 探索前先读

- 根目录 **`CONTEXT.md`**——本仓库是单上下文布局（无 `CONTEXT-MAP.md`）。
- **`docs/adr/`**——读与当前工作区域相关的 ADR。

这些文件不存在时**静默继续**：不要标出缺失，也不要建议预先创建。`/domain-modeling`（经 `/grill-with-docs` 与 `/improve-codebase-architecture` 触达）会在术语或决策实际敲定时惰性创建它们。

## 文件结构

```
/
├── CONTEXT.md        ← 领域词汇表（仅术语定义，无实现细节）
└── docs/
    ├── adr/          ← 不可逆决策记录，顺序编号
    └── background/   ← 已确认的外部产品输入（只读，不属于技能产物）
```

## 使用词汇表的术语

产出（issue 标题、重构提案、假设、测试名）命名领域概念时，使用 `CONTEXT.md` 定义的术语，不要漂移到词汇表明确回避的同义词。

需要的概念不在词汇表里是一个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记给 `/domain-modeling`）。

## 标出 ADR 冲突

产出与既有 ADR 矛盾时显式标出，不得静默覆盖：

> _与 ADR-0009（业务结果返回 HTTP 200）矛盾——但值得重开，因为……_
