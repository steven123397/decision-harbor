# DecisionHarbor 规范术语

本文档只维护 DecisionHarbor 首轮受治理查询链路中的规范语言和概念边界。实现取舍、接口和状态迁移见 [首轮受治理 SQL 查询链路设计](first-release-system-design.md)。

## 查询领域

### 受治理查询

用户提交的显式 SQL 经过策略判定，并且只在允许的对象范围和资源边界内使用分析只读身份执行。

- 推荐用词：受治理查询（`governed query`）
- 避免用词：任意查询、安全查询

### 查询运行

一次 `POST /api/v1/query-runs` 接受并处理 SQL 的完整尝试。每次查询运行拥有独立记录标识；用户重试会创建新的查询运行。

- 推荐用词：查询运行（`query run`）
- 避免用词：查询任务、查询会话

### 已接收

查询运行已经持久化，但尚未完成策略判定或进入分析数据库执行。

- 推荐用词：已接收（`received`）
- 相关概念：查询运行、运行中

### 运行中

查询运行已经通过策略判定，并已进入受资源限制的分析数据库执行阶段。

- 推荐用词：运行中（`running`）
- 相关概念：已成功、执行失败

### 已成功

分析数据库执行完成，并且终态审计事实已持久化。结果被截断但已明确标记时，仍属于已成功。

- 推荐用词：已成功（`succeeded`）

### 已拒绝

SQL 未通过治理策略，未进入分析数据库执行。已拒绝是预期的策略结果，不是系统故障。

- 推荐用词：已拒绝（`rejected`）
- 避免用词：执行失败

### 执行失败

查询已被系统接受，但因容量、数据库语义、超时、基础设施或进程中断而未成功完成。策略拒绝不属于执行失败。

- 推荐用词：执行失败（`failed`）
- 避免用词：策略拒绝

### 策略判定

SQL 策略模块对语句形态、对象范围、函数范围和禁止结构作出的 `not_evaluated`、`allowed` 或 `rejected` 结论。

- 推荐用词：策略判定（`policy decision`）
- 避免用词：权限检查

### 审计事实

平台数据库中持久化的原始 SQL、策略判定、引用对象、运行状态、资源边界、行数、耗时、错误摘要和时间信息。查询结果的单元格值不属于审计事实。

- 推荐用词：审计事实（`audit facts`）
- 避免用词：查询结果、应用日志

### 查询结果

一次成功请求即时返回的列定义和行数据。首轮不把查询结果持久化到平台数据库。

- 推荐用词：查询结果（`query result`）
- 相关概念：审计事实

## 数据库与身份

### 平台数据库

同一 PostgreSQL 容器中的 `platform` 逻辑数据库，保存查询运行和迁移状态等产品内生事实，不承载销售分析表。

- 推荐用词：平台数据库（`platform database`）

### 分析数据库

同一 PostgreSQL 容器中的 `analytics` 逻辑数据库；其中 `analytics` schema 承载固定销售分析数据，字段和口径由数据契约定义。

- 推荐用词：分析数据库（`analytics database`）

### 平台写入身份

API 运行时用于读写平台数据库产品表的数据库身份。该身份不能连接分析数据库。

- 推荐用词：平台写入身份（`platform writer`）

### 分析只读身份

查询执行器用于连接分析数据库的独立数据库身份。该身份只能读取明确授权的数据和就绪元数据，不能执行数据修改或访问平台数据库。

- 推荐用词：分析只读身份（`analytics reader`）

### 引导身份

仅供 Compose 初始化、迁移和 seed 一次性任务使用的数据库管理身份。Web 与 API 运行时不得获得该身份的凭据。

- 推荐用词：引导身份（`bootstrap identity`）

### seed 标记

记录已安装固定数据集的版本和摘要，用于判定重复 seed 是安全无操作还是数据冲突。

- 推荐用词：seed 标记（`seed marker`）
- 避免用词：数据版本表
