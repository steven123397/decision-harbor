# 领域术语

本文件只维护首轮规范词汇与概念边界。产品背景中的表名、字段名与业务口径以 `datasets/sales-analytics-v1/contract.json` 为准，此处不复述字段清单。

## 规范术语

| 术语 | 定义 |
| --- | --- |
| 查询运行（Query Run） | 一次用户 SQL 提交对应的平台侧记录与处理过程，含策略判定、可选执行与审计事实。 |
| 查询工作台 | Web 侧最小界面：输入 SQL、提交、展示执行中状态，以及结果表或拒绝/失败信息。 |
| 平台库（`platform`） | 保存产品状态（含查询运行审计）的逻辑数据库；仅平台可写身份访问。 |
| 分析库（`analytics`） | 保存固定销售分析数据的逻辑数据库；用户 SQL 仅能以分析只读身份在此执行。 |
| 平台可写身份 | 供 API 写入/读取 `platform` 的数据库角色；禁止用于执行用户 SQL。 |
| 分析只读身份 | 供查询执行器连接 `analytics` 的数据库角色；仅 `SELECT` 权限，且仅限授权业务表。 |
| 分析迁移身份 | 仅用于 `analytics` 的 schema 迁移与 seed 的高权限角色；运行时查询路径不得使用。 |
| SQL 策略（Policy） | 基于 SQLGlot AST 与对象访问范围的应用层校验；通过不代表可以绕过数据库权限。 |
| 策略拒绝（rejected） | 输入未通过策略；不进入分析库执行；仍写入查询运行审计。 |
| 执行失败（failed） | 策略通过后，执行阶段因超时、行数上限、数据库错误等原因失败。 |
| 执行成功（succeeded） | 策略通过且查询在资源限制内成功返回结果集元数据与行数据。 |
| 审计事实 | 与一次查询运行绑定、可事后读取的稳定字段：原始 SQL、状态、策略/错误信息、行数、耗时、时间戳等。 |
| 授权业务表 | 首轮允许出现在用户 SQL 中的 `analytics` 表：`customers`、`product_categories`、`products`、`orders`、`order_items`。 |
| 已实现销售 | 仅 `orders.status = confirmed` 的订单明细计入销售额与毛利；计算口径见背景与数据契约，本系统不物化冗余订单总额字段。 |

## 概念边界

- **策略通过 ≠ 业务正确**：策略只约束语句形态与对象范围；不解释业务语义，不改写用户 SQL 的分析含义。
- **应用策略与数据库权限是两道边界**：策略在 API 进程内强制执行；只读身份在 PostgreSQL 内强制执行。任一失败都不得导致跨库或写入分析数据。
- **结果集不是审计必存项**：审计必须保留运行元数据；完整结果行仅需在成功响应中返回给调用方，首轮不要求持久化结果网格。
- **健康与就绪分离**：`/health` 表示进程存活；`/ready` 表示依赖库可连且迁移（及必要 seed 标记）已完成。

## 避免的同义词漂移

| 不要混用 | 应使用 |
| --- | --- |
| 任务 / Job / 会话 | 查询运行（Query Run） |
| 权限系统 / 登录用户 | 首轮无终端用户身份模型；仅数据库角色边界 |
| 数据仓库 / 湖 | 分析库 `analytics`（单库固定数据集） |
