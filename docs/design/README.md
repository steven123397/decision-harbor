# 设计文档

本目录记录长期有效的边界、领域模型、接口、数据与关键决策。产品背景与约束仍以 `docs/background/` 为准；当前进展写在 `docs/status/`，不要把设计正文写进状态或计划。

## 正式文档

- [受治理查询链路](governed-query-path.md)：首轮范围、模块与数据流、查询运行、双库身份、策略、API、工作台、seed、Compose 与测试接缝。
- [规范术语](CONTEXT.md)：查询运行、审计事实、策略判定、对象访问范围、双身份与查询工作台。

尚未形成已确认决策时，不要在此目录批量创建专题文档。新增设计时使用下方模板，一篇文档只覆盖一个稳定主题。

## 模板

```markdown
# <主题>

## 范围

本文覆盖什么，不覆盖什么。

## 目标 / 非目标

- 目标：
- 非目标：

## 术语与场景

- 术语：只写本文引入且 `docs/background/` 未定义的概念。
- 场景：关键使用路径，不展开未确认能力。

## 不变量

实现必须始终成立的约束。

## 模块边界

模块职责、输入输出，以及不得泄漏到调用方的内部结构。

## 关键决策

已确认的取舍、理由和被拒绝的替代方案。

## 失败 / 迁移

失败语义、兼容性与迁移路径。

## 测试接缝

如何证明该设计仍然成立。

## 延后决策

明确未决项；不要把猜测写成结论。
```
