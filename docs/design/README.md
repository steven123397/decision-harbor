# Design 文档

`design/` 保存长期有效的产品内生设计。这里记录已经确认的边界和决策，不记录临时进度，也不重述 `background/` 中的外部输入。

## 何时新增设计文档

只有在存在真实的产品、架构、接口、数据或领域决策，并且该决策需要长期交接时，才新增专题文档。简单实现说明应留在代码或相关计划中。

## 最小内容结构

新的设计文档应根据实际需要覆盖以下内容：

1. 范围、目标和非目标。
2. 术语、概念关系和主要场景。
3. 不变量与约束。
4. 模块职责和接口边界。
5. 关键决策及其理由。
6. 失败处理、迁移和兼容性。
7. 测试接缝与验证方式。
8. 延后决策。

没有实际内容的章节可以省略；不要为了套模板创建空文档。
