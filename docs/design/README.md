# design 目录

长期边界、领域模型、接口、数据与关键决策。这里描述稳定的设计事实，不记录进度或临时计划。

## 何时新建设计文档

当某个模块或跨模块决策形成稳定结论、需要长期维护时建立专题文档；没有真实内容时不要批量生成。

## 模板

每篇设计文档按以下结构组织，无内容的小节可省略：

1. 范围：本文覆盖与不覆盖的边界。
2. 目标与非目标。
3. 术语与场景：涉及的领域概念与关键使用场景。
4. 不变量：必须始终成立的约束。
5. 模块边界：职责划分与交互方式。
6. 关键决策：决策、理由与被否决的备选。
7. 失败与迁移：异常路径、数据迁移与兼容策略。
8. 测试接缝：验证设计落点的测试位置。
9. 延后决策：明确推迟的决策及触发条件。
