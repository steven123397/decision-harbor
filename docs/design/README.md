# 设计文档（design）

## 职责

记录产品内生的长期设计：范围、领域术语、不变量、模块边界、接口、数据决策与已确认取舍。

这里写「系统应该如何构造」，不写当前做到哪一步（那是 `status/`），也不写任务排期（那是 `plan/`）。

## 何时新增文档

- 跨模块边界、数据模型、查询策略、API 契约或运行拓扑需要单独说清时。
- 背景需求已足够且无额外设计决策时，可暂不新增专题文档，在 plan 中注明「沿用 background」。

## 命名建议

- 专题设计：`docs/design/<topic>.md`（例如 `query-governance.md`、`local-runtime.md`）
- 领域术语：`docs/design/CONTEXT.md`（仅在确有术语统一需求时创建）

## 与背景的关系

`docs/background/` 是外部输入与已确认约束。设计可以细化实现结构，但不得改写背景中的业务口径、数据契约或首轮范围边界。
