# design/ 写作说明

本目录维护长期设计事实：只写会持续成立的边界与决策，不写阶段任务和进度。每个模块或专题一个文件，命名如 `query-governance.md`。领域术语统一维护在 [`CONTEXT.md`](CONTEXT.md)。

## 设计文档模板

```markdown
# <专题名>

## 范围
本文覆盖什么、不覆盖什么。

## 目标与非目标

## 术语与场景
仅列本专题特有用法；通用术语链接 CONTEXT.md。

## 不变量
无论实现如何演化都必须保持成立的约束。

## 模块边界
职责划分、对外接口、数据归属。

## 关键决策
每条决策写清结论、理由和被否决的备选。

## 失败与迁移
失败模式的处理方式；结构变化时的迁移路径。

## 测试接缝
验证本设计的关键位置与手段。

## 延后决策
明确暂不决定的问题及触发重议的条件。
```

没有真实内容的小节可以删除，不保留空标题。
