# design

本目录保存长期稳定的设计决策。阶段性的任务安排放 [plan/](../plan/)，当前事实放 [status/](../status/)。

## 收录范围

当一个决策会长期约束实现——例如模块边界、接口与数据设计、领域术语、不变量、关键取舍——并且后续实现者应直接依赖它时，写成 design 文档。一次性的实现细节、当前进度和任务拆解不属于本目录。

## 文档组织

- 每个主题一个文档，文件名使用小写连字符（如 `query-policy.md`）。
- 新增文档后更新 [../index.md](../index.md)。
- 领域术语以 [../background/product-requirements.md](../background/product-requirements.md) 和 `datasets/sales-analytics-v1/contract.json` 为既有权威；当设计沉淀出新的术语决策时，在 `CONTEXT.md` 集中维护，不提前复制背景定义。

## 模板

新文档从以下结构开始，按需裁剪：

````markdown
# <主题>

## 范围

本设计覆盖的模块与链路；明确不覆盖的部分。

## 目标与非目标

## 术语与场景

本主题引入或依赖的术语定义；触发该设计的代表性使用场景。

## 不变量

实现在任何路径下都必须保持的性质。

## 模块边界

职责划分、依赖方向和公开接口。

## 关键决策

每个决策给出选择、理由和被否定的替代方案。

## 失败与迁移

故障模式、回滚或数据迁移策略。

## 测试接缝

该设计对应的可验证层次与测试入口。

## 延后决策

已知但留待后续阶段处理的问题及触发条件。
````
