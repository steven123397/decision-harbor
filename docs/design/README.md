# 设计文档

本目录存放已收敛的长期设计：领域模型、接口契约、数据结构、关键决策及其理由。

## 何时写入

- 设计经过讨论或验证后收敛。
- 变更跨越 API、数据库、查询策略或运行环境时，同步更新受影响的设计文档。

## 文档模板

每篇设计文档建议包含以下结构（按需裁剪）：

```markdown
# <主题>

## 范围

本文档覆盖什么、不覆盖什么。

## 目标与非目标

- 目标：...
- 非目标：...

## 术语与场景

关键领域术语定义；核心使用场景。

## 不变量

系统必须始终满足的约束。

## 模块边界

涉及的模块、职责划分和交互方式。

## 关键决策

| 决策 | 选项 | 结论 | 理由 |
| --- | --- | --- | --- |

## 失败与迁移

故障处理策略；数据迁移或版本升级路径。

## 测试接缝

可验证点：单元测试、集成测试、端到端测试的切入位置。

## 延后决策

明确推迟到后续阶段的事项。
```

## 规则

- 没有真实内容时不要创建空壳专题文档。
- 新增文档后同步更新 `docs/index.md`。
