# 查询工作台

## 范围

本文定义 `web` 组件——最小查询工作台的界面结构、状态展示与 API 交互。前端不承担运营功能或视觉专项（背景非目标），一切从简。

## 目标与非目标

目标：让业务人员输入 SQL、提交、看到执行中状态，并阅读结果表格或稳定的拒绝、失败信息。

非目标：SQL 编辑器组件（语法高亮、补全）、查询历史列表、结果导出、图表、路由与多页面、状态管理库。理由：均超出"最小工作台"边界；纯 `textarea` + 原生 `fetch` + React 组件内状态即可覆盖需求，少一个依赖就少一分供应链与维护成本。

## 界面与状态

单页面，自上而下：SQL 输入区（多行文本框）、提交按钮、状态与结果区。

组件状态机（客户端本地）：

- `idle`：初始或上次结果保留展示中，可提交。
- `submitting`：请求在途，展示"执行中"，禁用提交按钮防止重复提交。同步执行模型下服务端 `running` 状态即请求在途，客户端无需轮询。
- 请求返回后按 `query_run.status` 展示：
  - `succeeded`：元信息行（行数、耗时，若 `truncated` 则显著提示"结果已按上限截断"）+ 结果表格。表格直接渲染 `columns` 名称与 `rows` 文本值，`null` 显示为空白样式。
  - `rejected` / `failed`：展示错误码与可读说明，并标注记录 `id` 以便追溯。
  - HTTP 422 / 网络失败：展示请求级错误，不伪装成查询结果。

新提交发出时清除上一次的错误；上一次成功结果保留到新结果返回，避免闪烁。

## API 交互

- 浏览器只访问 `web` 宿主端口；Vite dev server 将 `/api` 与 `/health` 代理到 `api` 服务。理由：单一入口免除 CORS 配置，浏览器测试与人工使用路径一致。
- 仅调用 `POST /api/v1/query-runs`；响应契约见 [query-runs-api.md](query-runs-api.md)。

## 测试接缝

为浏览器测试（Playwright）提供稳定 `data-testid`，视觉调整不得更名：

| testid | 元素 |
| --- | --- |
| `sql-input` | SQL 输入框 |
| `submit-query` | 提交按钮 |
| `query-status` | 状态指示（执行中/成功/拒绝/失败） |
| `result-table` | 结果表格 |
| `error-panel` | 错误码与说明区 |
| `truncation-notice` | 截断提示 |

浏览器主流程用例：

1. 提交合法 SQL：可见"执行中"→ 结果表格与行数出现。
2. 提交被禁 SQL（如 `DELETE`）：`error-panel` 展示 `policy_forbidden_statement` 与说明。
3. 提交期间按钮处于禁用态。

组件级逻辑（状态切换、响应渲染分支）用 Vitest 覆盖，不依赖真实后端。
