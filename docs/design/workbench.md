# 查询工作台

## 范围与目标

Web 端最小查询工作台：输入 SQL、提交、展示执行中状态，以及结果表格或拒绝/失败信息。响应结构见 [api.md](api.md)。

非目标：查询历史列表、多标签、图表、保存与分享、鉴权（背景已排除 RBAC 与图表编辑器）。

## 页面结构

单页应用，三个区域：

- **输入区**：SQL 多行文本框（等宽字体）与提交按钮。
- **状态区**：请求进行中按钮禁用并显示「执行中…」；这是背景要求的执行中状态，由同步请求的未返回呈现，不引入轮询。
- **结果区**：按 `outcome` 呈现三种形态之一——
  - `succeeded`：结果表格（列头来自 `result.columns`，单元格按文本渲染），附元信息行「共 N 行 · 耗时 X ms」；`truncated` 为真时追加「结果已截断，仅显示前 N 行」。
  - `rejected`：拒绝码与稳定可读说明。
  - `failed`：错误码与摘要。

## 行为约定

- 经同源路径 `POST /api/v1/query-runs` 提交（Nginx 反向代理，见 [architecture.md](architecture.md)）；无 CORS 配置。
- 数值与时间戳按字符串渲染，不做本地数值格式化（定点数以文本传输，见 [api.md](api.md)）。
- 网络错误或非 200 响应展示通用失败信息与 HTTP 状态；不解析协议层错误体之外的内容。
- 提交前不做事前校验：策略判定是 API 的职责，前端不复制规则，避免双写漂移。
- 空输入直接禁用提交按钮（纯 UI 行为，不算策略判定）。
