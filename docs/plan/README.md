# 计划文档

本目录记录阶段目标、任务切片、依赖、验证和交付边界。长期决策写在 `docs/design/`，当前事实写在 `docs/status/`。本目录不归档聊天记录，也不把背景需求改写成另一份需求。

尚未进入可执行阶段时，不要为未知工作编造计划正文。新增计划时使用下方模板。

## 模板

```markdown
# <阶段或垂直任务>

## 阶段目标

本阶段要交付什么，完成的判断标准是什么。

## 垂直任务

- 任务：可独立验证的切片
- 交付：代码、文档或数据的边界
- 验证：机械 / 行为 / 共识

## 依赖

前置条件、外部输入，以及被哪些后续任务依赖。

## 未规划区

本阶段明确不做的事项；不要用待办口吻写成下一步计划。

## 验证

- 机械：格式、类型、静态检查、已存在的仓库命令
- 行为：策略、接口、数据或主流程是否符合背景约束
- 共识：需要人确认的产品或设计取舍
```
