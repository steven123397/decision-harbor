# plan/ 写作说明

本目录维护阶段计划：目标、任务切片、依赖与验证方式。计划描述"接下来做什么、怎么算完成"；当前进展写在 [`status/project_status.md`](../status/project_status.md)，长期设计写在 `design/`。

每个阶段一个文件，命名如 `v0.1-query-pipeline.md`。计划完成或作废后就地标注结论；如未来需要归档再建立 `history_plan.md`。

## 计划文档模板

```markdown
# <阶段名>

## 阶段目标
本阶段交付什么、明确不交付什么。

## 任务切片
按可独立验证的垂直切片列出，每片写清入口、出口和涉及模块。

## 依赖
切片之间的先后关系与外部前置条件。

## 未规划区
本阶段明确不展开的部分及原因。

## 验证
- 机械验证：需通过的命令（测试、校验器、lint）。
- 行为验证：需人工或端到端确认的可观察行为。
- 共识验证：需与用户确认的取舍或验收点。
```
