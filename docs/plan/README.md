# plan

本目录保存阶段计划。长期设计决策放 [design/](../design/)，当前事实放 [status/](../status/)。

## 收录范围

每个交付阶段建立一个计划文档，文件名使用小写连字符并体现阶段（如 `m1-governed-query-loop.md`）。计划回答「这一阶段做什么、按什么顺序、如何验证」；阶段结束后，把长期决策沉淀到 `design/`、当前事实沉淀到 `status/`，然后移除旧计划文档，不采用历史归档目录。

## 文档组织

- 同一时间只维护一个活跃阶段计划。
- 新增文档后更新 [../index.md](../index.md)。

## 模板

新计划从以下结构开始，按需裁剪：

````markdown
# <阶段> 计划

## 阶段目标

本阶段交付的可验证成果与完成边界。

## 未规划区

明确不在本阶段处理、也不分配任务的范围。

## 垂直任务切片

每个切片跨越必要的层次并可独立运行验证；说明交付物与完成条件。

## 依赖与顺序

切片之间、切片与外部输入（如数据契约）之间的依赖。

## 验证

按层次列出验证方式：

- 机械验证：生成、校验、构建等命令级检查。
- 行为验证：单元、集成、浏览器测试。
- 共识验证：需要用户或评审确认的决策。
````
