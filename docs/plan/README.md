# 计划文档（plan）

## 职责

记录可执行的阶段目标、任务切片、依赖关系、验证方式与交付边界。

这里写「准备按什么顺序做什么、如何验收」，不写长期设计正文（`design/`），也不写实时进度日志（`status/`）。

## 何时新增文档

- 开始一轮实现或需要多步骤协作前，应有当前有效计划。
- 单次极小修复可直接在 status 中说明，不必强行建 plan。

## 命名建议

- 当前大计划：`docs/plan/<phase>-plan.md`（例如 `mvp-foundation-plan.md`）
- 垂直任务切片可放在同一计划的章节内；拆分过长时再拆文件
- 归档：`docs/plan/history_plan.md` 或 `docs/plan/archive/`（仅在项目采用归档时）

## 与 status 的关系

计划描述意图与验收；`docs/status/project_status.md` 描述当前真实进展。计划完成后更新 status，必要时将旧计划移入归档，避免多个「当前计划」并存。
