# 首轮交付

## 阶段目标

按 [受治理查询链路](../design/governed-query-path.md) 落地可运行的 Web、API 与 PostgreSQL 基座：AST 策略、只读执行、查询审计、最小工作台、幂等 seed、可并行 Compose，以及背景要求的 HTTP 接口与三类测试。

完成标准：统一启动后 `/health` 与 `/ready` 成功；允许查询返回结果并留下审计；拒绝查询不执行用户 SQL；策略单测、双库集成测与浏览器主流程通过。

## 垂直任务

- 任务：SQL 策略公共接缝与单元测试
- 交付：`api/` 策略模块
- 验证：机械 — pytest 策略套件；行为 — 允许/拒绝/对象范围/CTE/函数名单

- 任务：双库身份、迁移、幂等 seed、查询运行服务与 HTTP
- 交付：`api/`、`postgres/` 初始化、Alembic
- 验证：行为 — 三身份隔离、`/health` `/ready`、允许与拒绝查询、审计事实

- 任务：查询工作台与浏览器主流程
- 交付：`web/`、Vitest、Playwright
- 验证：行为 — 输入、执行中、结果表或拒绝信息

- 任务：可并行 Compose 与统一命令
- 交付：`compose.yaml`、`.env.example`、启动与测试入口
- 验证：机械 — 无固定容器/网络/卷名；行为 — 启动后健康检查

## 依赖

策略不依赖数据库。HTTP、审计、seed 依赖双库与三身份。工作台依赖 API。Compose 把三者编到同一可配置项目。

## 未规划区

异步查询、历史回放、登录、扩大函数名单、精确依赖版本冻结以外的发行策略。

## 验证

- 机械：`git diff --check`；`python3 datasets/sales-analytics-v1/validate.py`
- 行为：项目测试；Compose 启动；`/health`、`/ready`；允许与拒绝查询的 API 证据；浏览器主链
- 共识：不改背景契约与已实现销售额口径
