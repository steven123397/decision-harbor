# v0.1 首轮基座与受治理查询链路

## 阶段目标

按 [`docs/design/`](../design/README.md) 五篇设计交付首轮全部目标：可统一命令启动的 Web/API/PostgreSQL 基座、AST 与对象范围治理的只读执行、查询审计、最小工作台、契约数据迁移与幂等 seed、可并行 Compose 配置、四个 HTTP 端点及三层测试。不交付设计列明的非目标与延后决策项。

## 任务切片

1. **基座脚手架**：`compose.yaml`、`.env.example`、数据库初始化脚本（双库三身份）、`api/` 与 `web/` 容器定义、`dev.sh`。出口：`db` 服务可健康启动。
2. **策略模块**：pytest 表驱动单元测试先行，再实现 `policy` 纯函数（SQLGlot）。出口：设计列举的允许/拒绝/边界用例全绿。
3. **迁移与 seed**：platform 审计表迁移、analytics 契约五表迁移与授权、幂等 seed。出口：重复执行迁移与 seed 零破坏。
4. **执行器与 API**：只读执行器（超时/行上限/截断/序列化）、记录服务、四端点与错误码；集成测试覆盖身份边界与端到端。出口：集成测试全绿。
5. **工作台**：React 单页 + Vitest 组件测试。出口：组件测试全绿。
6. **浏览器主链**：容器化 Playwright 三条主流程用例。出口：`./dev.sh test` 全链通过。

## 依赖

1 先行；2 可与 1 并行；3、4 依赖 1（4 同时依赖 2、3）；5 依赖 4 的接口契约；6 依赖 4、5。

## 未规划区

生产部署、异步执行、函数白名单、用户体系——均为设计中的延后决策，本阶段不展开。

## 验证

- 机械验证：`./dev.sh test`（策略单元、集成、组件、浏览器测试）、`datasets/sales-analytics-v1` 的 `python3 validate.py`、`git diff --check`。
- 行为验证：`./dev.sh up` 冷启动与重复执行；`/health`、`/ready`；允许查询返回结果、被禁查询返回稳定错误码的 API 实证；工作台浏览器主链。
- 共识验证：完成后向用户汇报实现、验证证据与风险。
